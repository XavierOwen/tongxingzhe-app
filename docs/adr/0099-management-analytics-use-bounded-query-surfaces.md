# 管理分析采用受限且版本化的查询界面

状态：**已接受（2026-08-03）**，取代 ADR-0067。

关联：Slice 6；`ANALYTICS-007` 至 `ANALYTICS-014`、`PRIVACY-001` 至 `PRIVACY-011`、`TEST-005`。

## Context

精确聚合、最小单元阈值和互补隐藏可以降低直接披露风险，却不能证明一组重叠查询无法通过相减、外部资料或重建攻击恢复小群体信息。把这种方案写成“防止相减反推”会产生超过证据的安全承诺。首阶段也没有任意交互分析的产品需要，因此不应先开放通用查询构造器，再试图用查询历史检测补救。

## Decision

首阶段管理分析只提供服务端定义、版本化的固定报告形状。每个报告明确指标、单位、允许的维度、时间和区域粒度、筛选组合、排序、导出字段及隐私规则。请求在授权后先被 canonicalize 成有限的规范查询；未知维度、任意范围组合、自由下钻和客户端自定义 SQL 均拒绝。

后端在构造完整结果网格后统一执行 `k=10`、至少三位贡献者、单人贡献不超过一半、逐格隐藏和互补隐藏。API、图表和导出只接收抑制后的结果。测试使用相邻周期、重叠区域、互补类别、稀疏分组和已知外部事实进行重识别演练，并审计查询者、报告版本、规范查询指纹、时间和结果状态。

首阶段不加入随机噪声。产品和说明书只能声称这些控制减少披露风险，不能声称已获得形式化的不可重识别保证。若未来确需任意交互分析、连续自由下钻或更开放的数据访问，必须先建立新的隐私威胁模型和 ADR，并评估 differential privacy、隐私预算、准确度损失与查询组合规则。

## Options considered

- 精确聚合加连续查询检测：历史状态难以覆盖跨账号、跨导出和外部资料，不能形成可靠保证。
- 第一阶段直接使用 differential privacy：可能提供更强的组合推理，但会引入隐私预算、噪声解释和产品准确度取舍，当前固定报告不需要先承担这些复杂度。
- 只做单格阈值：无法处理总数、边际值和互补类别造成的恢复风险。

## Consequences

管理分析的产品自由度较低，但查询面可枚举、可复算、可审计，也更容易做负向测试。增加报告需要同时版本化定义、SQL、权限、网格抑制和重识别 fixture。即使所有测试通过，发布说明仍应把结论表述为风险控制证据，而不是数学上的匿名保证。
