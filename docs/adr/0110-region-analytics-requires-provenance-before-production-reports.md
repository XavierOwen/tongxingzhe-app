# 区域管理分析先证明来源和重叠边界，再注册生产报告

状态：**已接受（2026-08-12）**。

关联：Slice 6Q；ADR-0011、ADR-0012、ADR-0099；`REGION-005` 至 `REGION-009`、`ANALYTICS-007`、`ANALYTICS-012`、`PRIVACY-002` 至 `PRIVACY-006`、`PRIVACY-010`。

严格单父区域树只约束规范父链，不能证明多次报告的查询集合互不重叠。同一接触可能同时影响父区域和子区域汇总，也可能在区域树版本变更后进入另一范围；因此父子结果相减、跨版本比较和外部已知事实仍可能恢复小群体信息。区域报告不能只复用渠道报告的逐格阈值和总计隐藏。

首个区域工作单元只建立私有、fixture-first 的威胁探针，不注册生产区域报告，也不增加 runtime、HTTP、Flutter、缓存或导出入口。探针使用固定候选形状，识别父子或其他重叠范围、跨版本差分、共享期间值或隐藏状态变化、错误显示的小样本、互补关系和外部已知事实。结果只含版本化探针 ID、规范形状指纹、状态和类型化原因码，不含坐标、贡献者、隐藏值或生产授权证据。测试通过只能说明这些已枚举控制降低了披露风险，不能证明形式化不可重识别。

`original` 视图只可使用接触事实中保存的 `region_id + tree_version`。`current` 视图必须有明确的跨版本映射，或有可按当前发布边界重新解析的来源坐标；没有证据时必须保持不可归类，不能猜测城市。当前已解析接触不保留原始坐标，而且 `contact_region_assignments` 是会被后续 revision 覆盖的当前投影，所以本切片不声称已经能可靠生成两种区域视图。补齐追加式地点来源历史、冻结的区域版本或明确映射，是生产区域报告的前置工作。

`pending_resolution` 继续保留坐标并排除在城市格之外；它不是 `N/A`。`not_applicable` 只表示纯非线下接触没有区域地点。这两种状态不能合并、互相改名或作为任意区域的零值。

新增生产区域报告必须另立版本化工作单元，并同时固定指标单位、区域视图、树版本或映射来源、完整网格、互补隐藏、授权、快照 lineage 和重识别 fixture。不得通过给现有渠道报告增加自由区域参数来扩张查询面。
