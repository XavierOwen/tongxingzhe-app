# 项目报告时区变更由旧时区结束当前周期

状态：**已接受（2026-08-10）**。

关联：Slice 6；ADR-0062、ADR-0074、ADR-0099、ADR-0101；`ANALYTICS-001`、`ANALYTICS-004`、`ANALYTICS-012`。

项目报告时区使用追加式版本。首次配置从服务端接受请求的时刻生效，不倒写到请求前的周起点。后续变更由当前有效的旧时区计算下一个 ISO 周一 `00:00`，并在对应 UTC 时刻生效。旧时区因此负责结束当前尚未完成的周期；新时区、查看者设备和客户端字段都不能改变这个退出边界。

每个项目最多保留一个待生效版本。配置写入使用 UUID 幂等键、期望版本、变更请求锁和项目锁。相同业务请求的重试忽略新的服务端请求时间；不同参数不能复用幂等键。版本表拒绝普通修改和删除，未配置项目不回退 UTC。

本决定不修改 `release_management_report_snapshot_v1`，也不把后来创建的配置 revision 回填到既有快照。跨时区后，两份报告的期间边界和时区上下文不同，现有 6F/6G 发布判定仍须失败关闭。未来无时区参数的发布 v2 必须按可信数据截止点解析配置、把 revision 写入新快照，并另行固定跨时区 lineage 的隐私规则。
